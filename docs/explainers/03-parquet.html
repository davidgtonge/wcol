BEFORE THE BYTES / 01

What is Thrift?

Apache Thrift is an interface-definition language and a family of serialisation protocols. A schema gives each field a number and a type; Compact Protocol packs that information into small binary structures.

struct FileMetaData { 1: i32 version; … }
BEFORE THE BYTES / 02

Why does Parquet use it?

Parquet defines metadata in parquet.thrift and stores its Compact-encoded form in file footers and page headers. It uses Thrift as a file format encoding—not for network RPC, and not for the encoded column values.

parquet.thrift → Compact bytes → footer

FIELD HEADERS

Two nibbles, one byte.

The high nibble is the delta from the previous field ID; the low nibble identifies the wire type. A delta of zero means an explicit field ID follows.

SIGNED INTEGERS

Zigzag, then varint.

Negative and positive integers become small unsigned numbers before LEB128-style variable-length encoding. −1 → 1, 1 → 2.

NESTED STRUCTS

Field IDs reset per scope.

Every nested struct has its own delta context. The reader uses a scoped cursor, not a heap-allocated object tree or a heap-allocated nesting stack.

03 / OWNERSHIP

No generated metadata tree. No parser heap.

The input footer already exists as bytes in the transport's buffer. WCOL holds a borrowed slice, advances an offset, and emits a temporary view of each interesting column to a callback.

04 / THE BOUNDARY
Thrift describes the pages. It doesn't decode them.
The same Compact Protocol is used for Parquet page headers. The compressed page payloads use separate Parquet encodings and codecs. WCOL deliberately keeps these layers apart.

01 / I/O
Transport supplies the bytes.
An R2 or S3 range request supplies a slice of the object. The transport owns the input and the limits on how much is buffered.

      

      
01 / NOT MAGIC
Allocation-free codec ≠ no memory.
Footer bytes must be buffered contiguously for the current metadata parser. Streaming page decoders may need caller-owned scratch, presence bitmaps and decompression history.
02 / DEFENSIVE
Untrusted input needs limits.
Depth is bounded (64 by default); offsets, tags and varints are checked. Global footer-size and collection-count limits belong to the caller.
03 / FORWARD COMPATIBLE
Skip fields you don't need.
The parser can recursively skip unknown values or borrow their raw encoded bytes for rewriting. No full schema-generated object model is required.

    


    

      
05 / THE DECODERS
A page is a pipeline, not a blob.

01 / DICTIONARIESThe data page contains an ID, not a string.
The dictionary page decodes to caller-managed entries. The data page returns DictionaryId(index); the caller chooses when to resolve it.

        
02 / FLOATSRead four bytes, emit one f32.
PlainValues<f32> accepts fragmented input and retains at most a fixed-size partial value.

        
03 / BOOLEANSOne byte carries eight row values.
PlainBool reads the bits least-significant first and emits each row's boolean independently.

      

    


    
THE ENGINEERING TRADE-OFF
From an R2 byte range to a typed value.
Borrow the metadata. Decode page bytes incrementally. Keep scratch memory caller-owned. Reconstruct only the rows and values the query needs—that is the compact I/O foundation for WCOL.
