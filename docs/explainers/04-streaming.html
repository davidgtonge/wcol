CHAPTER 04 / STREAMING

A query in motion.

Parquet bytes are fetched on demand. Wasm processes bounded chunks. Streams connect scanners to reducers while the query is still running. When a consumer slows down, backpressure travels all the way upstream.

03 / LATE ARRIVALS & ENDING INPUT

Not attached is not EOF.

Distributed inputs arrive at different times. The stream pool must distinguish a port that may still attach, a stream that has reached EOF, and a producer that will never open an edge.

01 / ATTACH

It can arrive late.

createPoolInputLatch() stores pending attach/seal requests until the Wasm stream pool exists. There is no need to invent another fan-in buffer.

02 / EOF

A real stream has ended.

An attached input finishes via writer.close(), which triggers wcs_sp_in_end. The reducer can distinguish this from a missing producer.

03 / ABSENT

No stream was produced.

sealInput(port) calls wcs_sp_in_absent only for a port that never attached. The graph can finish without waiting forever.

04 / WHY THIS DESIGN WORKS

Bounded by construction.

The engineering constraints are part of the host API, not only comments in the query planner.

01 / BACKPRESSURE
⇄

A full slot stops the writer.

Input writes wait for wcs_sp_in_free; output reads release with wcs_sp_out_release. A slow consumer eventually stops the producer without an unbounded queue.

02 / NO BUSY POLL
◴

Work wakes on events.

Advancement is requested when slots change, reads complete, or host spill operations finish. The scheduler yields between batches rather than constantly spinning on a blocked graph.

03 / CONCURRENT PIPELINES
↝

Attach consumers early.

Reducer outputs can be connected to a running finalizer before all scans end. Consumption can start as soon as bytes are emitted, instead of filling a pipe with no reader.
